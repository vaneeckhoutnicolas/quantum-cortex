# The workshop and the public copy

*Added 2026-09-30 (ADR-004, amendment to D17 of that day). Stated so that no reader takes this repository for the whole of the author's files, and so that the commit identifiers cited in the record stay resolvable.*

This public repository is a **filtered copy of the author's private workshop repository**: the same commits, the same authors, the same dates, the same tags, with a declared set of files removed from every commit of the copy. What is public is everything the whitepaper and the record cite as evidence: the code, the tests, the benchmarks with their frozen thresholds, the artefacts and the retained logs, the ledger, the results, the architecture decision records, the ideas register with its dated revisions, the figures, and the mirror of the two hub pages that govern this repository (`docs/hub/`).

What stays in the workshop, removed from the copy's history:

- `docs/working/`: the handover prompts between the author's AI sessions, the resume notes, and the legal and provenance audit made before the tag (its decisions are in `NOTICE`, `LICENSE-DOCS.md` and `DISCLAIMER.md`);
- `CLAUDE.md`: the working rules given to the AI collaborator;
- `docs/HANDOFF-2026-08-07-ecosystem-context.md` and `docs/EXECUTION-2026-08-07.md`: a context capsule and an execution list written for the collaborator.

These files describe *how* the author works with a language model, which is his to keep; the method itself, at the level a reader can reproduce, is stated in the whitepaper (§2, §7b). Nothing in them is evidence: no number of the record depends on them, and the test suite does not read them.

**Commit messages.** The copy's commit messages are the workshop's with two trailers rewritten at the filtering, and nothing else changed: the links to the author's private working sessions are removed, and the co-author trailer of the commits written with the language model reads `Co-Authored-By: Claude ecosystem` in place of the model's version name and address. The paper says what the collaborator did (§2, §7b); the trailers say on which commits.

**Commit identifiers.** Filtering rewrites the identifiers of the commits it touches, so a commit identifier cited in a provenance file (`metrics/mqar/PROVENANCE-*.json`) refers to the workshop's history. The mapping from the workshop's identifiers to the copy's, produced by the filtering tool at the moment of the switch, is published here as `docs/COMMIT-MAP.txt` at the first public tag; a reader checks a cited commit by looking up its identifier in that file. The dates of every declaration are those of the workshop's commits, unchanged.

**What the copy is refreshed from.** The workshop remains the place where the work happens; the copy is refreshed from it at each tag, and between tags when a text of the copy changes (a contribution rule, an install line), always with the same filter, so that the two histories keep the same commits and dates from the first public tag onward. A refresh never rewrites what was already pushed: the filter is deterministic, so the commits already in the copy keep their identifiers and the push is a fast forward. No pull request is merged directly in the copy; a retained contribution is applied in the workshop with its author's name kept on the commit and arrives in the copy by the refresh (`CONTRIBUTING.md`).

**The package on the Python index.** `quantum-cortex` on PyPI is built from the public copy, not from the workshop: `python -m build` at the copy's commit, `twine check`, an upload by the author from an account protected by two factor authentication, the upload token revoked afterwards. Version 1.0.0 was built at the copy's commit `603dc21`, which is the `v1.0.0` tag (`6572467`) plus the two commits of the same night: the register's Rev86 and the packaging correction that made the four packages part of the wheel (the tag's own `pyproject.toml` packaged `cortex_data` only). The wheel carries `cortex_c2`, `cortex_c2b`, `cortex_data`, `cortex_eval` and `train.py`; the source archive carries in addition the tests, `README.md`, `LICENSE`, `LICENSE-DOCS.md`, `NOTICE` and `AUTHORS.md`; neither carries a working file, which was verified by downloading both from the index. A version on the index is never re uploaded: a correction is a new version, in step with the point releases.

*Dated 2026-11-11 (two precisions found at a handover and one amendment of the paragraph on the refresh, register Rev140; nothing above is rewritten).* **Signatures.** The author signs the workshop's commits with his key (ADR-010, section 9) and signed its release tag `v1.1.0` with it (the signature that the register's Rev137 reads on that tag is the workshop's tag object's). The copy's are not signed: filtering writes new commit and tag objects, and a rewritten object cannot carry the signature of the object it replaces (read on the copy at `121fc6f` that day: no signature on any of its 234 commits nor on any of its eight tag objects, the two release tags among them). A reader of the copy can therefore check its files against the hashes the record carries (the freeze list `metrics/mqar/FREEZE-v1.1.0.json`, the provenance files `metrics/mqar/PROVENANCE-*.json`), not against a signature of the author's key. **A commit with no counterpart.** A workshop commit that touches only removed files leaves nothing to write in the copy, and the filtering tool maps it to forty zeros in `docs/COMMIT-MAP.txt`. At this date there is one, `1d824db` (three working notes, 2026-11-03), which the scale probe's files of seed 7 name as a code commit (`docs/RESULTS.md`, row 53): the code those files ran is identified by the module's hash and by the freeze, equal on every session, and the files of the copy at that point are those of the commit before it (the workshop's `2d59e5c`, the copy's `433f81c`). Above, "the same commits" therefore reads: every workshop commit that touches a file kept in the copy, 234 of the 235 the map lists at this date. **Between tags (an amendment of "What the copy is refreshed from" above, which stays as written; the author, 2026-11-11, 15:27 Brussels).** That paragraph says that between tags the copy is refreshed "when a text of the copy changes". From this date a dated addition made in the workshop does not refresh the copy by itself: the copy is refreshed at each tag, and between tags only when a text of the copy is found false in a way a reader would act on or when the author asks for it. The dated additions made in between reach the copy at the next refresh, and until then the copy is behind the workshop by those additions. The copy is refreshed once with the commit that carries this line, so that it states its own rule. The practice had already departed from the letter of that paragraph before the tag `v1.1.0`: the eighteen commits of the copy dated 2026-10-15 to 2026-11-11 reached it in one push, with that tag.
