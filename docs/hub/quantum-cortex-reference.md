# quantum-cortex — the pure-LLM member of the ecosystem

**Status:** reference page, maintained in the hub. Recorded 2026-08-07 (founding day); repository created 2026-09-05 (E1). Repository: [`github.com/vaneeckhoutnicolas/quantum-cortex`](https://github.com/vaneeckhoutnicolas/quantum-cortex) (Apache-2.0, public).

## Separation of purposes (normative)

The Quantum Meridian repositories divide into two planes with distinct finalities:

- **Orchestration & data plane** — `quantum-agent` (VS Code agent, Cline fork), `quantum-proxy` (control-plane daemon, commercial), `quantum-contracts` (wire types), `quantum-metrics-dashboard` (private Rill/DuckDB usage observability). Their purpose: orchestrating agents, engines and tools, and observing that usage.
- **Model plane** — `quantum-cortex`: a **pure LLM**. It is **QM-compatible by default** (OpenAI-compatible endpoint, telemetry matching proposal scoring, journal-compatible events — its C6 surface) yet it is an **additional and independent element**: Quantum Meridian functions fully without it, and it functions fully standalone. No shared code, no shared dashboards (the cortex ships its own dedicated Rill project reading only its public run ledger), no licensing gates (fully open).

The trust boundary of the ecosystem is unchanged by cortex: only the inference path (prompts, completions, provider keys) never crosses the proxy; the cortex's persistent memory is agent-side, journal-backed, encrypted at rest (I13). What the organ guarantees under attack, by design and by measure, is stated in the cortex's whitepaper §4.9 (2026-09-30), and what the agents around it must guarantee is this hub's charge (cortex §1.6).
