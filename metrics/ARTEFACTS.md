# Where the artefacts live (checkpoints, journals, weights)

The record in git is the measurement: the hm-lm files, the session B files, the units, the retained logs, the provenance hashes and the ledger line with the run id and the configuration hash. The objects measured, checkpoints of hundreds of megabytes and sealed journals, stay where they were produced; this page says where, so that a rereading in six months knows where to go. A run id here is the one in `metrics/runs.jsonl`; a Kaggle version is identified by the run's start time in that ledger line (`timestamp_utc`), which is the version's run time.

Rules. A checkpoint is identified by its run id and its configuration hash, both in its `ckpt.pt` and in the ledger; `train.py` refuses a parent whose run id differs from the one the configuration names. A journal is sealed with the key of `QUANTUM_CORTEX_JOURNAL_KEY`, which is never written anywhere; a lost key is a lost journal. Weights go to a weights hub if a model is ever published, with the hash of the record that describes them, never into git. Kaggle keeps every version's Output; the relay keeps the last pushed state of a run during the run. The relay served a complete run directory once, seed 7 of v9 on 2026-09-30 (its checkpoint at step 7323 and its `hm-lm.json` identical to the committed one), by a manual download of the dataset; its pull path inside a Kaggle resume has still never been exercised with success, and that reserve stands.
