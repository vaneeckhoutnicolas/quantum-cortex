## 1. What this project is

`quantum-cortex` is an open-source (Apache-2.0) small language model with a novel architecture: the Quantum Meridian cognitive concepts — specialized zones, associative "magnetism", oracle-driven volatility, hard invariants — implemented **in the weights and the decode loop**, not in orchestration code around third-party models. It is the open traction engine of the Quantum Meridian ecosystem (open-core: cortex fully open, QM proxy commercial).

## 3. Architecture in six components (summary — hub decision 019 is normative)

- **C1 Zones** — mixture-of-experts routed toward semantic specialization, router learned with the model.
- **C2 Magnetism** — modern-Hopfield-style associative memory: in-weights layer (the ablatable research object) + persistent tier backed by the QM semantic journal.
- **C3 Volatility** — oracle channel: exogenous events injected mid-generation modulate routing temperature and gating → gray states, distributional bifurcation instead of 0/1.
- **C4 Invariants** — typed decode contracts (Kern legacy): constrained decoding, violations rejected at the source; determinism class declared per module (`deterministic | heuristic | stochastic`).
- **C5 Grafted zones** — external LLMs attach through the **same router interface** as internal experts (OpenAI-compatible adapter). Standalone = small cortex; plugged = same brain, larger zones.
- **C6 QM-native surface** — OpenAI-compatible endpoint + native telemetry matching QM proposal scoring (cache affinity / cost / latency / quota, weights 0.4 / 0.25 / 0.2 / 0.15) + journal-compatible events.

## 4. Differentiation thesis

Not competing with frontier general capability — that game is closed at individual budget. The winnable game: **capability per parameter at equal scale**. Gains must be capabilities (tasks the control model fails), not only efficiency. Every claim is benchmarked; losses are published.

## 5. Ablation protocol (summary)

Control = vanilla transformer at equal params / tokens / data / tokenizer / compute, pinned seeds, config hash per run. One component per ablation. Declared benchmarks: routing specialization (C1), MQAR-style associative recall (C2), oracle-shift adaptation (C3), invariant compliance rate (C4), plus perplexity and one small standard eval. Advancement rule: beat control on ≥ 1 declared capability with ≤ 2% perplexity degradation, tolerance stated before the run. Scale ladder 30M → 60M → 125M; 1–3B only for the validated combination.
